# Протокол Sound BlasterX G6 (SB1770)

Краткий справочник по тем командам, которые использует приложение. Данные
получены из публичных reverse-engineering-отчётов сообщества и перепроверены
на устройстве с прошивкой `2.1.201208.1030`.

## Транспорт

| Параметр | Значение |
|---|---|
| VID:PID | `041e:3256` |
| HID-интерфейс | 4 (в sysfs `…:1.4`), interrupt IN `0x85` |
| Запись | `SET_REPORT`, report ID `0`, 64 байта (hidraw: 65 байт с ведущим `0x00`) |
| Чтение | interrupt-передача, 64 байта |
| Драйвер | `usbhid`/hidraw |

Через hidraw ядро держит interrupt endpoint опрошенным, поэтому устройство
отвечает сразу. Если открывать устройство libusb/pyusb, потребуется
`USBDEVFS_RESET`, который на время ломает аудиопоток — так делать не нужно.

## Кадр

```
0x5a  CMD  LEN  payload…  (нули до 64 байт)
```

Ответы устройства:

| CMD | Смысл |
|---|---|
| `0x02` | ACK: `02 0a <команда> <статус> …`; статус `0` — успех |
| `0x11` | значение регистра (в т.ч. незапрошенный push) |
| `0x26` | глобальные флаги SBX/Scout/Voice Clarity |
| `0x2c` | выбранный выход |
| `0x3c` | усиление микрофона |
| `0x6c` | фильтр ЦАП |

## Регистры DSP

Адресация — пара `(family, feature)`, значение — IEEE-754 float32 little-endian.

```
чтение:   5a 11 03 01 <family> <feature>
ответ:    5a 11 08 01 00 <family> <feature> <f32>
запись:   5a 12 07 01 <family> <feature> <f32>
ответ:    5a 02 0a 12 00 …
```

Устройство после записи само присылает `0x11` с новым значением, а также
присылает пачки `0x11` при переключении выхода и нажатии кнопок на корпусе.
Пачка: `5a 11 <2+6n> <n> 00 [family id f32]×n`.

### 0x96 — воспроизведение

| ID | Параметр | Тип | Диапазон |
|---|---|---|---|
| `00` | Surround | bool | 0 / 1 |
| `01` | Surround level | float | 0…1 |
| `17` | Surround distance | float | 10…300, шаг 0,5 |
| `02` | Dialog+ | bool | 0 / 1 |
| `03` | Dialog+ level | float | 0…1 |
| `04` | Smart Volume | bool | 0 / 1 |
| `05` | Smart Volume level | float | 0…1 |
| `06` | Smart Volume mode | enum | 0 Normal, 1 Loud, 2 Night |
| `07` | Crystalizer | bool | 0 / 1 |
| `08` | Crystalizer level | float | 0…1 |
| `18` | Bass | bool | 0 / 1 |
| `19` | Bass level | float | 0…1 |
| `09` | EQ enable | bool | 0 / 1 |
| `0a` | EQ pre-amp | float | −6…+6, шаг 0,5 |
| `0b`…`14` | EQ 31 Гц…16 кГц (10 полос) | float | −12…+12, шаг 0,5 |

### 0x95 — запись

| ID | Параметр | Тип | Примечание |
|---|---|---|---|
| `00` | AEC (эхоподавление) | bool | |
| `04` | Voice Clarity / Noise Reduction | bool | |
| `05` | уровень шумоподавления | float | шкала устройства 0…0,5 (UI 0…100 %) |
| `13` | микрофонный EQ | bool | |
| `14`…`1b` | 8 полос микрофонного EQ | float | дБ; частоты неизвестны, в Windows только пресеты |
| `2c` | Smart Volume записи | bool | |

### 0x97 — декодер

| ID | Параметр | Значения |
|---|---|---|
| `02` | режим | 2 Normal, 1 Full, 3 Night |

## Глобальные команды

```
SBX вкл:      5a 26 05 07 01 00 01 00
SBX выкл:     5a 26 05 07 01 00 00 00
Scout вкл:    5a 26 05 07 02 00 01 00
Scout выкл:   5a 26 05 07 02 00 00 00
чтение флагов: 5a 26 03 08 ff ff  →  5a 26 0b 08 ff ff <mask> …
```

`mask`:

| Бит | Значение |
|---|---|
| `0x01` | SBX активен (любой эффект или EQ) |
| `0x02` | Scout Mode |
| `0x04` | обработка записи (Voice Clarity) |

Особенности:

* выключение SBX выключает все эффекты, но устройство помнит их состояние;
* если ни один эффект не был включён, включение SBX само включает Surround;
* запись отдельного эффекта при выключенном SBX включает только его;
* Scout и SBX взаимоисключающие.

## Выход

```
чтение:  5a 2c 01 01      →  5a 2c 05 01 <mode> 00 00 00
запись:  5a 2c 05 00 <mode> 00 00 00
```

`0x02` — колонки, `0x04` — наушники. После переключения устройство присылает
дамп профиля пачками `0x11`.

## Усиление микрофона

```
чтение:  5a 3c 02 01 00   →  5a 3c 04 01 00 02 <dB>
запись:  5a 3c 04 00 00 02 <dB>
```

`dB` — `0x00`/`0x0a`/`0x14`/`0x1e` = 0/10/20/30 дБ.

## Фильтр ЦАП (CS43131)

```
чтение:  5a 6c 01 01      →  5a 6c 03 01 <filter> 00
запись:  5a 6c 03 00 <filter> 00
```

`1` Fast Roll-off min phase, `2` Slow Roll-off min phase, `3` NOS,
`4` Fast Roll-off linear phase, `5` Slow Roll-off linear phase.

## Подсветка

```
вкл/выкл:     5a 3a 02 06 <0|1>
режим:        5a 3a 06 04 00 03 01 00 01
цвет:         5a 3a 09 0a 00 03 01 01 <A> <B> <G> <R>   (A=0xff)
чтение вкл:   5a 3a 01 07   →  5a 3a 02 07 <0|1>
чтение цвета: 5a 3a 06 0b 01 00 01 01 01 → 5a 3a 09 0b 01 00 01 01 A B G R
```

Порядок каналов именно `A B G R` (не RGBA). Поддерживается только статический
цвет.

## Direct Mode

```
вкл:    5a 39 03 00 05 01
commit: 5a 39 01 01
выкл:   5a 39 03 00 05 00 + commit
```

Команда перестраивает тактирование USB: устройство переподключается, hidraw-узел
на мгновение исчезает, transfer может вернуть `EPROTO`. Это нормально —
приложение переоткрывает устройство и перечитывает состояние. Состояние Direct
Mode устройство надёжно не отдаёт (ответ `5a 39 01 02` не декодирован), поэтому
приложение хранит его у себя.

## Микшер (не HID)

Громкости входов/выходов — стандартные USB Audio Class Feature Unit, доступные
как ALSA simple mixer controls карты G6:

| Windows | ALSA control |
|---|---|
| Playback: Speakers | `Speaker` |
| Monitoring: Line In / External Mic / S/PDIF In | одноимённые playback-контролы |
| Recording: Line In / External Mic / S/PDIF In / What U Hear | одноимённые capture-контролы |
| Recording source | `PCM Capture Source` (enum) |

Приложение работает с ними через `libasound` (ctypes), без `amixer`.

## Известные «странности» прошивки

* Значения по умолчанию у эффектов — нули, поэтому включение эффекта без
  уровня ничего не меняет; GUI при включении ставит 50 %.
* После переподключения часть регистров может читаться нулями до первой записи.
* Ответ на чтение приходит асинхронно, поэтому транспорт сопоставляет ответы по
  `(family, feature)` и таймауту, а не по порядку.
* На частые записи без пауз старое firmware иногда отвечает `EPROTO`; транспорт
  считает узел мёртвым и переподключается.
